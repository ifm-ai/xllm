Recommended configurations:

- gekko-0.9B: three knobs + `fp8_gemm=True`.
- gekko-4B: three knobs + `fp8_gemm=True` + `cuda_graph_block=True` (the graphs need the three knobs: with the
  default FSDP settings the per-layer re-all-gathers make the replay slower, 343 ms).
- gekko-7.1B: three knobs + `fp8_gemm=True` + `fp8_attn_dp=True` (the attention backward's dP = dO V^T GEMMs in
  MXFP8; opt-in because it puts the attention gradient path through e4m3 operands).

Where the time goes now (rank-0 traces): the steps are GPU-bound (4B with graphs 189 ms of kernels in a 200 ms
window, 7.1B 507 / 522, 0.9B 277 / 286); the MX GEMMs run at ~1.8 PFLOPS in situ against 3.0 isolated because the
1000 W cap lowers the clocks in the GEMM phases (SM clock 802-1965 MHz, 1737 average during 7.1B fp8 steps). The
SCA kernels are at 78-89% of the tensor-pipe issue rate, the bf16 GEMMs at peak.

Stage contributions (0.9B, 1 GPU, per step): swift SCA 671 ms -> CuTe SCA 3.8 ms per layer-pair (step 1151 ->
590 ms, peak memory 139 -> 40 GB); CUB TSDN 120 ms -> 2.3 ms; fused elementwise / norm kernels (55% of the
remaining step as torch ops) -> CuTe (527 -> 315 ms); FSDP knobs -8-15%; MXFP8 GEMMs -8 to -27% depending on the
GEMM share of the step.

Numerics: every kernel has a unit test against a fp32 reference (`tests/test_cute_*.py`, 130+ tests); end to end,
all-on vs all-off on the same batches gives loss differences <= 2e-4 and gradient-norm differences <= 1e-3 (bf16
items); fp8: 0.9B 100 steps mean loss difference +0.0009 (max 0.0105), 7.1B 30 steps max 0.001 (fp8_gemm +
fp8_attn_dp), 4B 60 steps with graphs: constant memory, no recaptures.

MXFP8 details: e4m3 elements, one e8m0 scale per 32 elements along K, fp32 accumulation, cuBLASLt via
`torch._scaled_mm` (SWIZZLE_32_4_4 scale layout); the activations / gradients / weights are quantised on the fly
(one Triton kernel per tensor writing both the rowwise and the colwise operand in one pass; the SwiGLU forward /
backward write their fp8 operands directly from the CuTe kernel; weights quantised once per step and kept for the
backward). cuBLASLt on Blackwell accepts MN-major MX operands, so no transposes are made. Per-tensor fp8 is ~6%
faster in the GEMM but worse numerically; rowwise fp8 ~15% slower (both measured, not used).
