# Parley improvement ideas observed while running the xLLM fault-tolerance rounds (operator notes)
1. Steers can arrive too late: run 1 ended before two inbox steers were read. Unread inbox lines should block DONE/synthesis.
2. A member endpoint died (Kimi engine crash) and the run went on with one member talking to itself. A down member should pause the run, alert the operator, and resume when it is back.
3. Reference paths are fixed at launch; adding sources mid-run meant copying files into an existing folder. Add an inbox command to mount a new read-only path.
4. Rounds are chained by hand (copy the previous artifact, a settled list, measurements). Add `parley continue <run>` that seeds the next round with the artifact, a frozen "settled" section and new evidence.
5. The citation check only proves the cited lines exist; wrong claims and overclaimed numbers passed it. Add a verifier pass that re-reads a sample of cited lines against the claim, and an assumption register: every number tagged measured / derived / assumed.
6. The team cannot run code, so it estimated what a 5-minute test would settle. Add a structured "request experiment" action that queues a test spec for the operator and feeds the result back into the run.
7. Discussion drifted into a deep side topic (async draft line review) while main deliverables waited. Add a deliverables checklist with per-item status and a moderator nudge when one item eats too many turns.
8. The whiteboard went stale against the discussion (fixed text still on it, deliverables only in chat). Check the whiteboard against the latest agreed text before DONE.
9. YAML quoting broke a launch (an apostrophe in the task). Add `--task-file`.
10. Monitoring needs a machine-readable status (round, speaker, open objections, unread inbox) instead of parsing minutes.md.
11. Symmetric roles: a built-in "propose and critique" role for every member, so no member only objects or only builds. Today the Architect/Challenger split had to be overridden mid-run by an inbox note.
12. Evidence posts from the operator should be first-class: a `measured:` inbox prefix that pins the result on the whiteboard as a fact (tagged with the job id and script) so later turns cannot drift back to the old estimate.
13. Attach artifacts mid-run: operator test scripts and logs had to be copied into an existing reference folder by hand to be readable. An inbox command such as `/attach <path>` should mount them read-only.
14. Coverage of requirements, not just files: a requirements checklist (from the task and from operator notes) that the team must mark as covered / not covered / fallback before DONE; the user asked for "all cases" and it is easy to drop some.
15. Notes on how the operator's messages appear: inbox lines show as "You - moderator" turns; label them by source (user requirement vs operator measurement vs operator opinion) so the team weighs them correctly.
16. Cross-review is mandatory, not a role: every member must, each turn, comment on the other members' latest proposals and propose concrete corrections (a structured "Review of <name>: agree / disagree + evidence / correction" block), whatever role they hold. A turn without a review of the others is sent back.
17. Round limit with no agreement: today, when max_rounds is reached the loop just ends and the synthesizer writes the final answer anyway (session.py:627, then _synthesis), so open disagreements can be silently decided by the synthesizer. Instead: (a) if objections are still shrinking, auto-extend by a bounded number of rounds; (b) otherwise end with status NOT CONVERGED and a "Disagreements" section listing each open point with both positions and evidence; (c) in every non-converged case, OFFER extra rounds: write the open points to questions.md and wait (with a timeout) for the operator to grant N more rounds, steer, or accept the disagreement; in batch mode with no answer, auto-grant one bounded extension before ending as NOT CONVERGED.
